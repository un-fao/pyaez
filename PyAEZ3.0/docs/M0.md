# Module 0: data retrieval and preparation

The input data required by an agro-ecological zoning analysis are different and can be hard to be retrieved. Moreover, data retrieval and preparation require expertise with climatic, geographical and edaphic data, limiting the usage of the methodology for those people who are not acquinted with these subjects. To easy the first-approach to PyAEZ, Module 0 creates nominal input data for all the following modules of PyAEZ. Specifically, in Module 0 users can request the following tasks:

1. Retrieve data for Module 1: Module 0 can download climatic data from CAVA (link!), prepare che rasterized boundary layer for the selected country, 
2. Retrieve data for Module 2: Module 0 can retrieve reference crop parameters (expert users can insert country-specific or variety-specific parameters). 
3. Retrieve data for Module 3: Module 0 can retrieve reference crop-specific climate contraints (expert users can insert country-specific or variety-specific climate constraints). 
4. Retrieve data for Module 4: (Rut & Shahla)

In the following section, a detailed description of the data retrieval operations for each modules is reported.

## Input data for Module 1

In **Module 1**, users can gather and prepare the following datasets:

- **Climate data**:  
  Minimum and maximum temperature, precipitation, solar radiation, wind speed, and relative humidity.  
  PyAEZ supports both **daily** and **monthly** formats.

- **Country boundaries**:  
  A vector file (e.g., shapefile or GeoJSON) delineating national borders for spatial masking and analysis.

- **Digital Elevation Model (DEM)**:  
  Elevation data used for terrain analysis and to support agro-climatic computations.

- **Soil/terrain and special-purpose land cover classes**:  
  Specifically, the dataset `soil_regime_CRUTS32_Hist_8110`, available under the **Agro-ecological Zones** sub-theme of [**GAEZ v5**](https://data.apps.fao.org/gaez/?lang=en).

Within Module 1, the following geospatial operations are performed as shared processing blocks across all input datasets:

- **Rasterization**:  
  Converts vector data (e.g., country boundaries) into raster format for compatibility with other layers.

- **Uniform resolution harmonization**:  
  Ensures all raster datasets share the same spatial resolution for accurate overlay and analysis.

- **Masking with country boundaries**:  
  Clips all input layers to the extent of the selected country to reduce processing time and focus analysis.


### Climatic data from CAVA

Climate and Agriculture Risk Visualization and Assessment (CAVA) is an approach to climate information with a focus on agriculture. Its goal is to provide long-term, climate services by democratising access and simplifying the use of past and future climate and impact data.
CAVA offers two main components:

1. CAVA Platform: a freely accessible and user-friendly platform for climate and impact information
2. CAVAanalytics: dedicated R package providing advanced analyses and harmonized access to raw data used by the CAVA Platform

It is developed through a collaboration between the Food and Agriculture Organization of the United Nations an the University of Cantabria. CAVA uses dynamically downscaled climate model outputs at 25 km resolution from the CORDEX-CORE simulation framework, consisting of a standardized set of high-resolution regional climate simulations produced under the CORDEX-COmmon Regional Experiment (CORE) framework, coordinated by the World Climate Research Programme (WCRP). Dynamical downscaling approach applies Regional Climate Models to lower resolution Global Climate Model outputs as boundary conditions. Additionally, CAVA uses the bias-corrected reanalysis dataset W5E5 as an observation data for the historical period.

[`cavapy`](https://github.com/Risk-Team/cavapy) is a Python library developed starting from the CAVAanalytics experience and designed to streamline the retrieval of CORDEX-CORE climate models. CAVA data are hosted on THREDDS servers at the University of Cantabria, which provides a web service specifically designed for distributing large scientific datasets, along with an efficient storage system. Using the Open-source Project for a Network Data Access Protocol (OPeNDAP), users can directly access and subset datasets without the need to download large NetCDF files. This capability is part of the Climate and Agriculture Risk Visualization and Assessment (CAVA) project, which focuses on providing high-resolution climate data for scientific, environmental, and agricultural applications.

With `cavapy`, users can efficiently integrate CORDEX-CORE data into their workflows, making it an ideal resource for hydrological and crop modeling, among other climate-sensitive analyses. Additionally, cavapy enables bias correction, potentially enhancing the precision and usability of the data for a wide range of applications.

### UN Boundaries

To guarantee compliance with UN standards, users are allowed to use boundaries prescribed by the United Nations. To properly work with the following module, the vector UN boundaries are rasterized matching the resolution and the spatial projection of the climatic data.  

### Digital Elevation Model

The median altitude at 30 seconds spatial resolution, made available from [GAEZ v5](https://data.apps.fao.org/gaez/?lang=en), is provided to the users. This layer is rasterized matching the resolution and the spatial projection of the climatic data.   

### Soil/terrain and special purpose land cover  

The soil/terrain and special purpose land cover corresponds to the dataset `soil_regime_CRUTS32_Hist_8110` available under the **Agro-ecological Zones** sub-theme of [**GAEZ v5**](https://data.apps.fao.org/gaez/?lang=en). This land cover raster is made available automatically in module 0 and is rasterized matching the resolution and the spatial projection of the climatic data.
